# 摄像头补丁 MatebookUVCFix 0.3.0（2026-11-07，Claude）

## 根源
- 摄像头 AzureWave/IMC 13d3:56c6 是 UVC 1.5（bcdUVC 0x0150），视频协商 PROBE/COMMIT 的 GET_CUR 固定回 48 字节。
- macOS 自带 UVC 驱动只按 UVC 1.0/1.1 要 26/34 字节 → 控制传输溢出 0xe00002e8 → 没画面。两边都是固定行为，只能在内核里拦截这几个请求。
- 11-06/11-07 四次内核崩溃：0.2.1 把数据写进调用者（UVCAssistant）的内存描述符时没有先 prepare()，内核报 "IOGMD: not wired for the IODMACommand"。

## 0.3.0 改了什么
- 一个 kext 覆盖 macOS 13–26（Darwin 22–25），取代 0.1.1（只认 22.1.0）和 0.2.x（只认 24H232 的 UUID）。
- 安全闸：函数符号名（包含完整参数签名）＋ 函数开头 17 字节；已核对 13.0 (22A380) 与 15.8.2 (24H232) 完全相同。不符就自动停用，不会乱改。
- 写调用者内存一律在 prepare()/complete() 之间；不能写的描述符直接交回苹果原代码。
- 305 个导入符号在 13 与 15 内核＋Lilu 1.7.2 里全部找到；单元测试（ASan/UBSan）通过；OpenCore 1.0.8 ocvalidate 无问题。

## 部署（内置 EFI）
- Kexts/MatebookUVCFix.kext = 0.3.0（MinKernel 22.0.0，MaxKernel 25.99.99）
- MatebookUVCFix-Sequoia.kext（0.2.2）条目已停用，文件保留
- 旧 0.1.1 改名为 Kexts/MatebookUVCFix-0.1.1-before-uvc030.kext
- 原配置：EFI/OC/config-before-uvc030-20261107.plist

## 已验证（macOS 15.8.2）
- 0.3.0 已加载；直接对摄像头发 26/34 字节 GET_CUR：修复前 0xe00002e8，修复后成功并返回正确前缀；48/64 字节不受影响；无新崩溃。
- 未验证：登录后真正打开摄像头出画面；macOS 13 下的开机与摄像头。

## 回退
复制 EFI/OC/config-before-uvc030-20261107.plist 为 config.plist，并把 MatebookUVCFix-0.1.1-before-uvc030.kext 改回 MatebookUVCFix.kext。开机参数 -mbuvcoff 可临时停用补丁。
